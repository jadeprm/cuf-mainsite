# chulafair.com

เว็บไซต์หลักของจุฬาฯแฟร์ 2027 — ธีม **D(R)AWN to the Zenith** ท้องฟ้ายามรุ่งอรุณ เส้นขอบฟ้า และสีตาม CI

- สองภาษา ไทย / English (ปุ่มสลับมุมขวาบน จำภาษาที่เลือกไว้ให้)
- หน้าแรกย้ำ **"รอรายละเอียด เร็ว ๆ นี้"** ทั้งในส่วนหัวและการ์ดประกาศ
- ปุ่ม **สตาฟ / Staff** เล็ก ๆ มุมขวาบน → `https://task.chulafair.com` (และ `chulafair.com/staff` ก็พาไปที่เดียวกัน)
- หน้า **จัดการเว็บไซต์** ที่ `chulafair.com/admin` — เข้าได้เฉพาะ **Admin และ Co-Admin ของ CUFTM** ด้วยบัญชีเดียวกับ CUFTM
- สร้าง **หน้าใหม่** (ออกแบบ/ประกาศ) และ **บล็อก** ได้เอง พร้อมดูตัวอย่างสด ฉบับร่าง ประวัติการแก้ไข และย้อนกลับได้
- มีหน้า **แบบสำรวจความสนใจร่วมเปิดร้านค้า** สร้างไว้แล้วเป็น **ฉบับร่าง (ยังไม่เผยแพร่)** ที่ `/p/shop-interest` — ย้ำชัดว่า *ไม่ใช่ใบสมัคร*

## สิทธิ์แก้ไขทำงานอย่างไร

เว็บนี้ **ใช้ฐานข้อมูลเดียวกับ CUFTM** และอ่านตาราง `users` ของ CUFTM เพื่อตรวจรหัสผ่าน (อ่านอย่างเดียว ไม่เคยเขียน)

| ใน CUFTM | ที่ chulafair.com/admin |
| --- | --- |
| Admin, Co-Admin | เข้าได้ แก้ได้ทุกอย่าง |
| Editor, หัวหน้าหน่วย, สมาชิก | เข้าไม่ได้ (ขึ้นข้อความว่าไม่ใช่ Admin) |
| ถูกระงับ / ถูกลบออกจากชีต | เข้าไม่ได้ทันที |
| ยังไม่ตั้งรหัสผ่าน / รอรีเซ็ต | ต้องไปตั้งที่ task.chulafair.com ก่อน |

- อยากให้ใครแก้เว็บได้ → ตั้ง Access ของคนนั้นเป็น Admin หรือ Co-Admin ในชีตของ CUFTM แล้ว Sync — ไม่มีรายชื่อแยกให้ดูแลอีกชุด
- ลดสิทธิ์ใน CUFTM แล้ว เขาจะถูกตัดออกจากหน้าจัดการเว็บ **ในคำขอถัดไปทันที** ไม่ต้องรอ cookie หมดอายุ
- ตารางทั้งหมดของเว็บนี้ขึ้นต้นด้วย `site_` จึงไม่ชนกับตารางของ CUFTM
- ใส่รหัสผิดเกิน 8 ครั้งใน 15 นาที ชื่อผู้ใช้นั้นจะถูกพักการเข้าสู่ระบบชั่วคราว

> ⚠️ ถ้าวันหนึ่ง CUFTM เปลี่ยนชื่อคอลัมน์ในตาราง `users` (`username`, `access`, `password_hash`, `password_salt`, `active`, `suspended`, `reset_allowed`, `display_name`) ต้องแก้ `lib/auth.js` ของเว็บนี้ตามด้วย

## ติดตั้งครั้งแรก (ประมาณ 20 นาที ไม่ต้องใช้ command line)

### 1. เอาโค้ดขึ้น GitHub
1. GitHub → **New repository** → ชื่อ `chulafair-site` → **Private** → Create
2. คลิก **uploading an existing file** → ลากไฟล์และโฟลเดอร์ทั้งหมด *ข้างใน* zip นี้ (`api`, `lib`, `public`, `package.json`, `vercel.json` …) วางลงไป → **Commit**
   - ไม่ต้องอัปโหลด `node_modules` ถ้ามี

### 2. สร้างโปรเจกต์ใหม่บน Vercel (แยกจาก CUFTM)
1. Vercel → **Add New… → Project** → เลือก `chulafair-site` → **Import**
2. Framework Preset: **Other** — ไม่ต้องเปลี่ยนอย่างอื่น → **Deploy**
3. โปรเจกต์นี้มีฟังก์ชันแค่ **2 ตัว** (`api/admin.js`, `api/render.js`) ห่างไกลจากเพดาน 12 ตัวของแพ็กฟรี

### 3. เชื่อมฐานข้อมูลเดียวกับ CUFTM (สำคัญที่สุด)
1. Vercel → แท็บ **Storage** → เปิดฐานข้อมูล Neon ตัวที่ CUFTM ใช้อยู่ (อย่าสร้างตัวใหม่)
2. **Connect Project** → เลือก `chulafair-site` → Connect (Vercel จะตั้ง `DATABASE_URL` ให้เอง)
3. แท็บ **Deployments** → อันบนสุด → **⋯ → Redeploy**

ไม่เชื่อมฐานข้อมูล หน้าแรกยังเปิดได้ (ใช้ข้อความตั้งต้น) แต่ `/admin` จะขึ้นว่ายังไม่ได้เชื่อมฐานข้อมูล

### 4. ผูกโดเมน chulafair.com
1. Vercel → โปรเจกต์ `chulafair-site` → **Settings → Domains** → เพิ่ม `chulafair.com` และ `www.chulafair.com` (ให้ www redirect ไป chulafair.com)
2. ที่หน้าจัดการ DNS ของ **z.com** ใส่ระเบียนตามค่าที่ Vercel แสดงในหน้า Domains โดยปกติคือ
   - `A` ชื่อ `@` → `76.76.21.21`
   - `CNAME` ชื่อ `www` → `cname.vercel-dns.com`
3. ⚠️ **อย่าแตะระเบียน MX / TXT ของอีเมล** และ **อย่าเปลี่ยน Nameserver ไป Vercel** — อีเมล `@chulafair.com` ที่ z.com จะใช้ไม่ได้
4. `task.chulafair.com` เป็นของโปรเจกต์ CUFTM แยกกัน ไม่เกี่ยวกับขั้นนี้

### 5. ลองใช้
- เปิด `chulafair.com` → สลับ TH/EN มุมขวาบน
- เปิด `chulafair.com/admin` → เข้าสู่ระบบด้วยบัญชี CUFTM (ต้องเป็น Admin/Co-Admin)

## อัปเดตเว็บเป็นเวอร์ชันใหม่

เมื่อได้ไฟล์ zip เวอร์ชันใหม่ ให้เอาไฟล์ขึ้น **repo เดิม** ที่ Vercel ผูกไว้ แล้ว Vercel
จะ deploy ให้เองอัตโนมัติภายใน 1–2 นาที ไม่ต้องสร้างโปรเจกต์ใหม่และไม่ต้องตั้งโดเมนใหม่

1. แตก zip ออก
2. เปิด repo ของเว็บบน GitHub → **Add file → Upload files**
3. เลือกไฟล์และโฟลเดอร์ทั้งหมด*ข้างใน* `chulafair-site` ลากวางลงกล่องอัปโหลด
4. **Commit changes** → Vercel จะขึ้นงาน deploy ใหม่เอง ดูได้ที่แท็บ Deployments

⚠️ การลากไฟล์ขึ้น GitHub จะ **เพิ่มและเขียนทับ** แต่ **ไม่ลบ** ไฟล์เก่าที่ไม่มีในชุดใหม่
ถ้าเวอร์ชันใหม่ตัดไฟล์ไหนออก ต้องไปลบไฟล์นั้นใน GitHub เองด้วย (เหมือนที่เคยเจอกับ CUFTM)

เปลี่ยนแค่ข้อความหรือรูปบนเว็บ **ไม่ต้อง deploy ใหม่** — แก้ใน `/admin` ได้เลย
การ deploy ใหม่มีไว้สำหรับการเปลี่ยนตัวโค้ดเท่านั้น

## เว็บขึ้นว่า "ยังไม่ได้เชื่อมฐานข้อมูล"

หน้า `/admin` จะบอกเองว่าเซิร์ฟเวอร์มองเห็นตัวแปรอะไรบ้าง (แสดงเฉพาะ*ชื่อ*ตัวแปร
ไม่แสดงรหัสผ่าน) ไล่ตามนี้

1. **ยังไม่ได้ Redeploy** — สาเหตุที่พบบ่อยที่สุด ตัวแปรจะเข้าถึงได้เฉพาะ deployment
   ที่สร้าง*หลัง*จากเชื่อมฐานข้อมูลแล้ว ไปที่ **Deployments → อันบนสุด → ⋯ → Redeploy**
2. **เชื่อมฐานข้อมูลเข้าโปรเจกต์นี้หรือยัง** — Vercel → โปรเจกต์ `chulafair-site` →
   **Storage** ต้องเห็นฐานข้อมูลของ CUFTM อยู่ในรายการ ถ้าไม่มี ให้เปิดฐานข้อมูลนั้น
   แล้วกด **Connect Project** เลือกโปรเจกต์นี้
   *(การเชื่อมที่ฝั่งโปรเจกต์ CUFTM ไม่ได้ทำให้โปรเจกต์นี้เห็นฐานข้อมูลด้วย ต้องเชื่อมแยก)*
3. **ตัวแปรถูกตั้งชื่อมีคำนำหน้า** — ตอนเชื่อมฐานข้อมูลเดิมเข้าโปรเจกต์ที่สอง Vercel
   จะถาม *Environment Variables Prefix* ถ้าใส่ไว้ ตัวแปรจะกลายเป็นเช่น
   `CUFTM_DATABASE_URL` — เว็บนี้รองรับชื่อแบบมีคำนำหน้าแล้ว จึงใช้งานได้เลย
4. **เชื่อมฐานข้อมูลไว้มากกว่าหนึ่งอัน** — ถ้าหน้า `/admin` ขึ้นว่า *เชื่อมฐานข้อมูลได้
   แต่ไม่ใช่ฐานข้อมูลของ CUFTM* แปลว่าโปรเจกต์มีฐานข้อมูลเชื่อมอยู่หลายตัวและหยิบผิดตัว
   (เช่นเผลอกด Create Storage สร้างอันใหม่เปล่า ๆ ขึ้นมา) หน้าดังกล่าวจะบอกว่ากำลังใช้
   ตัวแปรชื่ออะไรอยู่ ให้ไปที่ Vercel → **Storage** → เปิดฐานข้อมูลที่*ไม่ใช่*ของ CUFTM →
   แท็บ **Projects** → **Remove / Disconnect** โปรเจกต์นี้ออก ให้เหลือเชื่อมไว้อันเดียว
   แล้ว **Redeploy**

   ฐานข้อมูลของ CUFTM คือตัวที่โปรเจกต์ CUFTM ใช้อยู่ — สังเกตจากวันที่สร้าง ซึ่งจะเก่ากว่า
   และกด **Browse data** แล้วต้องเห็นตาราง `users`, `tasks`, `meetings` อยู่ข้างใน

หน้าแรกของเว็บยังเปิดได้ตามปกติระหว่างที่ยังไม่เชื่อมฐานข้อมูล (ใช้ข้อความตั้งต้น)
มีแต่ `/admin` กับหน้าที่สร้างเองเท่านั้นที่ต้องใช้ฐานข้อมูล

## ใช้งานหน้าจัดการ (chulafair.com/admin)

**หน้า & บล็อก**
- **+ หน้าใหม่** — หน้าทั่วไป อยู่ที่ `chulafair.com/p/<ลิงก์>` ติ๊ก "แสดงในเมนูด้านบน" ได้
- **+ เขียนบล็อก** — โพสต์อยู่ที่ `chulafair.com/blog/<ลิงก์>` เมื่อมีโพสต์เผยแพร่แล้ว เมนู "อัปเดต" และส่วน "อัปเดตล่าสุด" บนหน้าแรกจะโผล่ขึ้นเอง
- กรอกทีละภาษาด้วยแท็บ **ไทย / English** — ช่องภาษาอังกฤษที่เว้นว่างจะแสดงข้อความไทยแทน
- **ดูตัวอย่าง** — เปิดตัวอย่างสดด้านขวา สลับไทย/EN/มือถือได้ ยังไม่ต้องบันทึก
- **บันทึกฉบับร่าง** ไม่มีใครเห็นนอกจากผู้ดูแล — **เผยแพร่** แล้วทุกคนเห็น (อัปเดตบนเว็บจริงภายในราว 1 นาที)
- **รูปแบบหน้า: แบบสำรวจ** — ใส่กล่อง "ไม่ใช่ใบสมัคร" ตัวใหญ่ และปุ่มไปยังลิงก์แบบสำรวจ (ถ้ายังไม่ใส่ลิงก์ ปุ่มจะขึ้นว่า "ลิงก์แบบสำรวจจะเปิดเร็ว ๆ นี้")
- **สีประจำหน้า** — เลือกจากพาเลต CI 6 สี ใช้กับท้องฟ้าส่วนหัวและการ์ด
- **ประวัติการแก้ไข** — ทุกครั้งที่บันทึก ฉบับก่อนหน้าจะถูกเก็บไว้ 30 ฉบับล่าสุด กด "ย้อนกลับไปฉบับนี้" ได้
- ถ้ามีคนสองคนแก้หน้าเดียวกันพร้อมกัน คนที่บันทึกทีหลังจะถูกเตือนแทนที่จะเขียนทับงานอีกคน

**ข้อความหน้าแรก** — แก้สโลแกน บรรทัดวันที่ ข้อความ "เร็ว ๆ นี้" เกี่ยวกับงาน อีเมลติดต่อ และลิงก์โซเชียล (ช่องที่เว้นว่างจะถูกซ่อน)

**ผู้สนับสนุน** — อยู่ในเมนู "ข้อความหน้าแรก" หัวข้อ *หน้าแรก — ผู้สนับสนุน* แบ่งเป็น 4 ระดับ ไล่จากใหญ่ไปเล็ก

| ระดับ | ชื่อตั้งต้น | ขนาดโลโก้ |
| --- | --- | --- |
| 1 | สปอนเซอร์หลัก | ใหญ่สุด กรอบเน้นสีลาเวนเดอร์ |
| 2 | สปอนเซอร์รอง | รองลงมา |
| 3 | สปอนเซอร์สมทบ | เล็กลงอีก |
| 4 | ผู้สนับสนุนอื่น ๆ | เล็กสุด |

กรอกรายชื่อ **บรรทัดละหนึ่งราย** รูปแบบ `ชื่อ | ลิงก์รูป | ลิงก์เว็บ`

```
บริษัท ก จำกัด | https://ลิงก์รูปโลโก้.png | https://เว็บของเขา.com
บริษัท ข จำกัด | https://ลิงก์รูปโลโก้2.png
ร้าน ค
```

- ใส่แค่ชื่อก่อนได้ ยังไม่มีโลโก้ก็จะแสดงเป็นป้ายชื่อแทน แล้วค่อยเติมลิงก์รูปทีหลัง
- ลิงก์เว็บใส่หรือไม่ใส่ก็ได้ ถ้าใส่ โลโก้จะกดได้
- ระดับที่เว้นว่างจะไม่แสดงเลย ไม่เหลือช่องว่าง
- ถ้ายังไม่มีผู้สนับสนุนเลย จะขึ้นกล่อง "รายชื่อผู้สนับสนุนจะประกาศเร็ว ๆ นี้"
- ถ้าอยากซ่อนส่วนนี้ทั้งหมด ให้ลบ "หัวข้อส่วนผู้สนับสนุน" ทั้งไทยและอังกฤษ
- ชื่อแต่ละระดับแก้ได้ทั้งไทยและอังกฤษ

**รูปภาพ** — เว็บนี้ยังไม่มีที่เก็บไฟล์ ให้อัปโหลดรูปไว้ที่อื่นก่อน (เช่น Canva แชร์ลิงก์รูป) แล้ววางลิงก์ที่ลงท้าย `.jpg` / `.png`

## ไฟล์ในโปรเจกต์

```
api/render.js     หน้าเว็บสาธารณะทั้งหมด (หน้าแรก, /p/…, /blog, /blog/…)
api/admin.js      API ของหน้าจัดการ (เข้าสู่ระบบ, หน้า, บล็อก, ตั้งค่า, ตัวอย่าง)
lib/view.js       เทมเพลต HTML ของหน้าเว็บ
lib/content.js    ข้อความหน้าแรกที่แก้ได้ + ผู้สนับสนุน + ค่าตั้งต้น
lib/auth.js       ตรวจบัญชี CUFTM และเซสชันของเว็บนี้
lib/db.js         ตารางฐานข้อมูล site_* + หน้าแบบสำรวจตั้งต้น
lib/md.js         แปลง Markdown อย่างปลอดภัย (ไม่ยอมให้ใส่ HTML/สคริปต์)
public/           CSS, JS, หน้า admin, ไอคอน, รูปแชร์ og.png
dev/, test/       สำหรับทดสอบในเครื่องเท่านั้น (ไม่ถูก deploy)
```

ทดสอบในเครื่อง (ต้องมี Postgres ในเครื่อง): `DATABASE_URL=postgres://…@localhost/… npm test`
